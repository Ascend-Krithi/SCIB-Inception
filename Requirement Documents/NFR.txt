Non-Functional Requirements (NFRs) List

Security
- All API endpoints must enforce OAuth2 authentication and RBAC for parent/youth/admin roles
- Input validation on all user and API inputs (no negative, zero, or non-numeric transfer/limit values)
- Output filtering to prevent data leakage
- Audit logging for all critical actions (fund transfer, limit changes, dashboard access)
- Data encrypted at rest and in transit (TLS 1.2+)
- Regular security assessments and automated vulnerability scans

Compliance
- GDPR: Data minimization, subject access, right to erasure
- PCI-DSS: Secure handling of payment-related data, logging, and monitoring
- ISO 27001: Adherence to organizational controls

Performance
- 95% of API requests respond in <200ms
- Dashboard page load <500ms under normal load
- Fund transfer and limit updates processed within 1s

Scalability
- API and web tiers must support horizontal scaling
- DB must support read replicas for reporting and analytics

Availability
- Service must maintain 99.99% uptime (cloud HA deployment)
- Automated failover for critical services

Reliability
- ACID-compliant transactions for fund movements
- Ledger integration for transaction immutability
- Retry logic for transient failures

Maintainability
- Modular architecture with documented APIs
- Automated code quality checks and code reviews
- OpenAPI/Swagger docs for all endpoints

Auditability
- All user actions logged with user ID, timestamp, and action details
- Logs retained for a minimum of 7 years for compliance

Disaster Recovery
- RTO <4 hours, RPO <1 hour
- DR tested quarterly

Backup
- Daily encrypted backups of all databases
- Automated restore tests monthly

Monitoring
- Real-time system health metrics and alerting
- Centralized log aggregation (e.g., ELK/Splunk)

Logging
- Structured logs for all APIs and services
- Logs stored securely, access-controlled

RBAC
- Role-based access enforced in all APIs and UI components
- Regular RBAC policy review and automated test coverage

Testability
- Automated API and UI tests for all business rules and error paths
- Coverage for negative, boundary, and concurrency scenarios

Concurrency
- Support for concurrent parent/youth access with strict data consistency
- Optimistic locking or DB-level transactions to prevent race conditions

---
All NFRs are mapped to design decisions and test scenarios in the HLD and traceability matrix.
