# Non-Functional Requirements (NFRs): Youth Account Parental Controls

## Security
- OAuth2 authentication for all APIs
- RBAC: Only parents/guardians can manage youth accounts they own
- Input validation and output filtering (PII masking)
- All fund transfers and limit changes audit logged

## Compliance
- GDPR: Data minimization, right to access, erase
- PCI-DSS: Secure fund transfer, encryption in transit and at rest
- ISO 27001: Controls for access, logging, DR

## Performance
- 95% API responses < 500ms under normal load
- UI loads dashboard in < 2s for typical data sets

## Scalability
- Horizontal scaling of API and DB components
- Support >10,000 concurrent parent sessions

## Availability
- 99.99% uptime SLA
- Highly available cloud deployment, failover in <60s

## Reliability
- ACID transactions for fund movements
- Retry logic for external service calls

## Maintainability
- Modular service boundaries
- OpenAPI/Swagger spec for all endpoints
- Code and API documentation

## Auditability
- All fund allocations, spending limit changes, and transaction retrievals logged with user, timestamp, and action
- Tamper-evident logs

## Disaster Recovery
- RTO < 4 hours, RPO < 1 hour
- Regular DR drills and DB restores

## Backup
- Daily full backups, encrypted at rest
- Backups stored in geographically separate location

## Monitoring
- Real-time API, DB, and UI metrics
- Alerting for failures, SLA breaches, security events

## Logging
- Centralized log aggregation (transactionId correlation)
- Retention policy: 1 year

## RBAC
- Role-based access enforced at API and UI layers
- Only parents/guardians assigned to youth account can perform actions

## Other
- Input validation, output filtering, and error handling per API spec
- Automated and manual penetration testing
